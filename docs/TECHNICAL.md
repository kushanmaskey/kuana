#### Staging Workflow — `.github/workflows/deploy-staging.yml`

**File location:** `.github/workflows/deploy-staging.yml`  
**Trigger:** Manual only (`workflow_dispatch`) — go to GitHub → Actions → Deploy to Staging → Run workflow  
**Build mode:** `--mode staging` — Vite loads `client/.env.staging` which sets `VITE_API_URL=https://kuana.onrender.com`  
**Deploy target:** `public_html/staging.kuana.org/`

```yaml
name: Deploy to Staging

on:
  workflow_dispatch:       # Manual trigger only — no automatic deploys
```

```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest   # GitHub spins up a fresh Ubuntu VM for every run
```

**Step-by-step breakdown:**

| Step | What it does |
|---|---|
| `actions/checkout@v4` | Downloads the full repo code onto the GitHub runner VM |
| `actions/setup-node@v4` | Installs Node.js 20. `cache: 'npm'` caches `node_modules` keyed by `client/package-lock.json` — subsequent runs skip re-downloading unchanged packages |
| `npm ci` | Installs exact dependency versions from `package-lock.json` (stricter than `npm install` — fails if lock file is out of sync) |
| `npm run build -- --mode staging` | Vite compiles all React JSX, CSS, and assets into optimized static files in `client/dist/`. The `--mode staging` flag tells Vite to load `client/.env.staging` so the API URL points to the Render backend |
| `Setup SSH` | Creates `~/.ssh/id_ed25519` from the `SSH_PRIVATE_KEY` GitHub Secret. `chmod 600` is required — SSH refuses keys that are world-readable. `ssh-keyscan` adds the GoDaddy server's host fingerprint to `known_hosts` so SCP doesn't prompt for confirmation |
| `Deploy via SCP` | Copies every file in `client/dist/` recursively to the GoDaddy server. The trailing `/` on `client/dist/.` means "copy contents, not the folder itself" |

```yaml
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: client/package-lock.json   # cache key

      - name: Install dependencies
        run: npm ci              # deterministic install from lock file
        working-directory: client

      - name: Build
        run: npm run build -- --mode staging   # loads client/.env.staging
        working-directory: client

      - name: Setup SSH
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.SSH_PRIVATE_KEY }}" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519                        # required by SSH
          ssh-keyscan -H p3plzcpnl475181.prod.phx3.secureserver.net >> ~/.ssh/known_hosts

      - name: Deploy via SCP
        run: |
          scp -r -i ~/.ssh/id_ed25519 -o StrictHostKeyChecking=no \
            client/dist/. \
            ${{ secrets.SSH_USERNAME }}@p3plzcpnl475181.prod.phx3.secureserver.net:public_html/staging.kuana.org/
```

#### SSH Key Setup (one-time)

If the SSH keys need to be regenerated (e.g. after a security incident or key expiry):

1. Generate two Ed25519 key pairs locally:
   ```bash
   ssh-keygen -t ed25519 -C "kuana-staging-deploy" -f ~/.ssh/kuana_staging
   ssh-keygen -t ed25519 -C "kuana-prod-deploy" -f ~/.ssh/kuana_prod
   ```

2. Add each **public key** (`*.pub`) to GoDaddy:  
   GoDaddy → Hosting → cPanel → SSH Access → Manage SSH Keys → Import Key → Authorize

3. Add each **private key** to GitHub:  
   GitHub → Repository → Settings → Secrets and variables → Actions → New repository secret:
   - `SSH_PRIVATE_KEY` → contents of `~/.ssh/kuana_staging`
   - `PROD_SSH_PRIVATE_KEY` → contents of `~/.ssh/kuana_prod`
   - `SSH_USERNAME` → GoDaddy cPanel username (e.g. `enynjq3aag57`)

4. Test by running the Deploy to Staging workflow from GitHub Actions.

#### Troubleshooting Deployments

| Symptom | Likely cause | Fix |
|---|---|---|
| Workflow fails at "Setup SSH" | `SSH_PRIVATE_KEY` or `PROD_SSH_PRIVATE_KEY` secret missing or malformed | Re-add the secret in GitHub Settings — must include full key including `-----BEGIN...` and `-----END...` lines |
| Workflow fails at "Deploy via SCP" with permission denied | SSH public key not authorized on GoDaddy | Re-authorize the public key in GoDaddy cPanel → SSH Access → Manage Keys |
| Workflow fails at "Deploy via SCP" with "No such file" | `public_html/staging.kuana.org/` directory doesn't exist on server | Create it via GoDaddy cPanel → File Manager |
| Site shows old version after deploy | Browser cache | Hard refresh (`Cmd+Shift+R`) or open in incognito |
| Site shows old version but cache cleared | SCP uploaded to wrong path | Check deploy logs in GitHub Actions for the exact SCP destination path |
| Build fails with "Cannot find module" | `npm ci` not run or `node_modules` out of sync | Run `npm ci` locally in `client/` to reproduce |

## 5. Authentication & Authorization  <!-- was §4 -->

### Method
- **JWT (JSON Web Token)** signed with `JWT_SECRET`
- Token lifetime: **8 hours**
- Stored client-side in `localStorage` under key `kuana_token`
- Sent on every authenticated request as `Authorization: Bearer <token>`

### Middleware — `server/middleware/auth.js`

```js
function requireAuth(req, res, next) {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Unauthorized' });
  }
  const token = authHeader.split(' ')[1];
  try {
    req.admin = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    return res.status(401).json({ error: 'Invalid or expired token' });
  }
}
```

### Token Payload

```json
{
  "id": 1,
  "email": "admin@kuana.org",
  "role": "admin",
  "iat": 1700000000,
  "exp": 1700028800
}
```

### Key Queries Per Route

| Route | Query | Parameterized |
|---|---|---|
| Login | `SELECT * FROM admins WHERE email = $1` | ✅ |
| Setup | `INSERT INTO admins (name, email, password_hash) VALUES ($1,$2,$3)` | ✅ |
| Get events | `SELECT * FROM events WHERE is_published = true ORDER BY event_date DESC` | ✅ |
| Get event | `SELECT * FROM events WHERE id = $1` | ✅ |
| Alumni search | Dynamic with ILIKE `%$1%` | ✅ |
| Register alumni | `INSERT INTO alumni (...) VALUES (...)` | ✅ |
| Soft delete alumni | `UPDATE alumni SET is_active = false WHERE id = $1` | ✅ |
| Contact submit | `INSERT INTO contact_messages (...)` | ✅ |
| Get contacts | `SELECT * FROM contact_messages ORDER BY created_at DESC` | ✅ |
| Mark read | `UPDATE contact_messages SET is_read = true WHERE id = $1` | ✅ |
| Mark unread | `UPDATE contact_messages SET is_read = false WHERE id = $1` | ✅ |
| Toggle event featured | `UPDATE events SET is_featured = $1, updated_at = NOW() WHERE id = $2` | ✅ |
| Donation submit | `INSERT INTO donations (...)` | ✅ |
| Donation stats | `SELECT COUNT(*), SUM(amount), AVG(amount), COUNT(DISTINCT donor_email) FROM donations WHERE status = 'completed'` | ✅ |
| Get media | `SELECT m.*, e.title as event_title FROM media m LEFT JOIN events e ON m.event_id = e.id WHERE m.is_published = true` | ✅ |

> ⚠️ All queries use parameterized statements (`$1`, `$2`, ...). **SQL injection is not possible.**

### Summary Tab

The Alumni tab uses a `COLUMNS` constant (defined module-level) that drives both table display and Excel export:

|---|---|---|---|

**Column checkboxes:** Admins select which columns to display in the table. The same selection controls which columns appear in the exported Excel file. All columns are visible by default.

## 10. Debugging Guide with Examples

### 10a. Login Fails with 401

**Symptom:** `POST /api/auth/login` returns `{ "error": "Invalid credentials" }`

**Check:**
```bash
# Verify admin exists in DB
psql $DATABASE_URL -c "SELECT id, email, role FROM admins;"

# Test bcrypt hash manually (Node REPL)
node -e "const b=require('bcryptjs'); b.compare('mypassword', '<hash_from_db>').then(console.log);"
```

**Common causes:**
- Wrong email (case-sensitive in DB, but login lowercases via JS — verify)
- Password was hashed with a different cost factor
- Admin doesn't exist — run `/api/auth/setup` first

---

### 10b. 429 Too Many Requests

**Symptom:** Rate limiter blocks requests during development.

**Fix:** Restart the server (in-memory rate limit resets) or temporarily raise the `max` in the route file. Do NOT disable in production.

---

### 10c. JWT Token Expired

**Symptom:** Admin page shows login screen unexpectedly.

**Debug:**
```js
// Paste in browser console
const token = localStorage.getItem('kuana_token');
const payload = JSON.parse(atob(token.split('.')[1]));
console.log('Expires:', new Date(payload.exp * 1000));
```

**Fix:** Log in again. Token lasts 8 hours.

---

### 10d. Database Connection Fails

**Symptom:** All API calls return `500 Server error`.

**Check:**
```bash
# Test DB connection directly
psql $DATABASE_URL -c "SELECT NOW();"

# Check env var is set
echo $DATABASE_URL
```

**Common causes:**
- `.env` file missing or `DATABASE_URL` not set
- SSL mismatch (`rejectUnauthorized` vs self-signed cert)
- DB server not running

---

### 10e. Alumni Register Returns 409

**Symptom:** `{ "error": "Email already registered" }` (PostgreSQL error code `23505` — unique violation).

**Example input that triggers it:**
```json
{ "first_name": "Kushan", "last_name": "Maskey", "email": "kushan@example.com" }
```
(when `kushan@example.com` already exists in `alumni` table)

**Fix:** Use a different email, or check the DB:
```sql
SELECT id, first_name, last_name, email FROM alumni WHERE email = 'kushan@example.com';
```

---

### 10f. Media Images 404 in Production

**Symptom:** Gallery images from `/assets/img/gallery/2025/` don't load after deployment.

**Cause:** Local images in `client/public/assets/img/gallery/` must be committed to git. Vite copies everything in `client/public/` into `client/dist/` at build time, and the GitHub Actions deploy workflow uploads `client/dist/` to the server via SCP.

**Fix:**
```bash
git add client/public/assets/img/gallery/
git commit -m "Add 2025 gallery images"
git push
# Then run "Deploy to Staging" or "Deploy to Production" in GitHub Actions
```

---

### 11g. CORS Error in Development

**Symptom:** `Access to XMLHttpRequest blocked by CORS policy`

**Fix:** Ensure Vite proxy is configured in `client/vite.config.js`:
```js
server: {
  proxy: {
    '/api': 'http://localhost:4000'
  }
}
```
And that the backend is running on port 4000. If you changed `PORT` in `.env`, update the proxy target to match.

---

### 11h. Contact Form Email Not Arriving

**Symptom:** Form submits successfully (200 response) but no email arrives.

**Check Render logs** (Render dashboard → kuana → Logs) for:
```
Email send failed: ...
```

**Common causes and fixes:**

| Cause | Fix |
|---|---|
| `RESEND_API_KEY` not set on Render | Add it in Render → Environment |
| `MAIL_TO` not set on Render | Add `info@kuana.org` in Render → Environment |
| Render SMTP blocked (old Gmail setup) | Resend uses HTTP API — not affected by SMTP blocks |
| `kuana.org` domain not verified on Resend | Emails send from `onboarding@resend.dev` until domain verified |

**Test email directly (without the web form):**
```bash
cd server
node -e "
require('dotenv').config();
const { sendContactEmail } = require('./utils/mailer');
sendContactEmail({ name: 'Test', email: 'test@example.com', subject: 'Test', message: 'Hello' })
  .then(() => console.log('Sent!'))
  .catch(e => console.error(e.message));
"
```
